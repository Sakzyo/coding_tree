## Finding and smallest implementation

I2 remains present in current source: OpenCode `createRoutes` still binds an unconditional new-root `activation_unavailable` (`packages/opencode/src/server/routes/instance/httpapi/server.ts:271–278`). The earlier preflight is a proposal, not an implemented fence. Its producer inventory remains substantially accurate, with two important additions below: HTTP asynchronous admission must own a claim **before** its fork/204, and promotion callbacks can outlive the background job scope.

Use one narrow **legacy Session-domain process-local activity registry**, in new `packages/opencode/src/session/legacy-activity.ts`, and a same-domain M2 repository association decorator. The registry owns only canonical-root exclusion and exact volatile claims. Existing Session Runner and BackgroundJob continue to execute work. M2 continues to own root identity, association and membership queries. Host wiring binds public ports. This requires neither another execution loop nor a durable claim table, migration, V2 coordinator change or Session-ID service layer.

The source contract calls for current-process shared coordinators (`high-level-design.md:51–52,238–255`), and explicitly rejects a separate daemon as unnecessary for the first desktop version (`:39`). Therefore current-process app-owned legacy activity is the justified first implementation scope. It cannot establish idle in other OS processes, external terminals, or arbitrary escaped plugin/tool descendants. Do not describe it as an OS-wide fence. Independently hosted deployment modes without that authority retain unavailable activation; M9 isolation and all managed provider/tool execution remain disabled.

## Required public ports

The registry's independently constructible scoped factory exposes these conceptual interfaces; implementation names may follow local conventions:

```ts
acquire(root, verifyUnmanaged): Effect<Lease, ExecutionUnavailable>
retain(lease): Effect<Lease, ExecutionUnavailable>
release(lease): Effect<void>
withAssociation(root, commit): Effect<ProjectContext, AssociationError>
```

`Lease` is a runtime-only exact opaque object bound to one captured canonical root and owner instance; release is idempotent for that exact object. A stale release cannot affect a later claim. `retain` requires a currently held lease and publishes a separate held claim before child acceptance/fork. It must not rediscover an arbitrary root from job metadata. Acquiring work in another stored Session root requires that root's own canonicalization/check, not a retain of the parent root alone.

`verifyUnmanaged` is M2's bound live association check, executed while the root exclusion is held immediately before publishing a claim. No caller boolean, status snapshot or serialized permit is accepted. The registry never queries M2 or Session tables. The Opencode adapter obtains the stored Session through `Session.Service`, obtains accessible canonical identity through M2's filesystem adapter, then supplies M2's borrowed-database check to acquisition. Add one narrow public canonical-root resolution operation in `FtcProjectAdapters` using its existing `canonical` implementation; preserve the existing `legacy(db)` refusal signature for callers. The M2 association lookup remains private to M2.

`commit` is the actual M2 repository association effect for the same already validated folder. Root exclusion remains held through durable write success/failure/cancellation; returning an idle snapshot before the write is insufficient. Borrowed database effects must not be retained as registry-wide fields after an operation.

Change `FtcProjectAdapters.activation` from a FolderIdentity precheck to a **Repository/Lookup decorator** overriding `associate(folder)`. `FtcProjects.make` already validates identity before `repository.associate(folder)` (`projects.ts:283–296`), so its public signature need not change. Composition supplies pure `input.folders` and the decorated repository. Replace `FtcComposition.Ports.activate` / `ftcHost`'s callback with the scoped association port. Existing associations can reconcile/open without new activation; the decorator checks them through M2 and only fences new association. Recheck durable association in the fenced commit so concurrent opens reconcile the same association after waiting. No M2 SQL schema changes are required.

Keep the existing canonical `activation_unavailable` error for both unresolved authority and a retryable occupied root, optionally using `detail` to distinguish known activity. The task/brief permit typed unavailable/busy; a new `activation_busy` code is a useful optional UI distinction, not necessary for the smallest fence. Adding it would require explicit Schema ownership, generated Client refresh and corresponding canonical contract tests. Never weaken `legacy_execution_disabled` on associated roots.

## Concrete generic lifecycle seams

Runner needs one optional acquisition hook for newly accepted execution items, returning an exact release/terminal obligation. Place it on `Runner.make` options or on accepted work inputs; bind it in SessionRunState using the captured runtime Session/root permit. The hook's contract must include failure before acceptance, duplicate join, queued acceptance, transfer, cancellation before start, actual work scope closure and owner shutdown. It must not add FTC imports to generic Runner. Run acquired work within its own cleanup scope and invoke terminal release only after that scope closes; merely adding onExit around an effect whose children are still elsewhere is insufficient. Keep the existing state machine/result fan-out.

BackgroundJob needs one analogous optional **runtime** ownership input/factory hook, no field in serializable Info or metadata. Exact accepted start/extension obligations belong to the existing job token generation, and release occurs after the exact job scope and pending work close, including the asynchronous terminal path. Promotion obtains its own retained obligation before onPromote escapes. The legacy wrapper/TaskTool binds actual captured root permits; Core implements only the generic lifecycle seam. Tests of Core BackgroundJob need no M2 or Opencode boot. No hook may treat status=completed as terminal cleanup.

Command shell-template expansion is a separate demonstrated cleanup gap: `prompt.ts:1419–1427` uses `Effect.promise(() => Promise.all(Process.text(...)))` without forwarding abort or awaiting cleanup on interruption. The Process utility supports abort and awaits process exit plus output-stream buffers (`util/process.ts:57–106,113–136`). Forwarding Effect's AbortSignal alone does not make the cancelled Effect await that outstanding promise. Prefer the existing scoped ChildProcessSpawner already supplied to SessionPrompt, preserving shell/notthrow/output behavior; alternatively retain ownership until the actual Process.text promise settles during cancellation. No utility rewrite is preassigned. Use the exact scoped API and explicit terminal join, never assume cancelling a Promise cancelled its OS process.

## Actual host sharing

`HttpApiApp.webHandler` supplies the existing shared Core memo map (`httpapi/server.ts:328`); AppRuntime supplies it at `effect/app-runtime.ts:111`. Actual `Server.listen` builds with a **new** memo map per listener (`server/server.ts:125`). A graph-global node alone therefore creates separate owners.

Export a pure stable registry layer and a live binding which explicitly builds that layer through `@opencode-ai/core/effect/memo-map` **using the requesting graph's Scope**. Only that narrow owner is shared. No import-time ManagedRuntime, database capture, unrelated cache merge or global reset. Wire the binding into every legacy owner node dependency and into OpenCode's FTC association callback. Pure test factories remain fresh scoped instances. Source changes to `app-runtime.ts` and `server/server.ts` are only needed if the narrow binding cannot be supplied through existing node dependencies; do not preemptively replace either host's whole memo map.

Dispose one graph without closing the registry while other graph borrowers/work remain. Last-owner shutdown rejects new claims and must not declare roots idle before registered owners finish; place dependencies so registry teardown cannot deadlock ahead of producer teardown. Test graph close and reopen while asynchronous cleanup is paused. All same-process production graphs must query the same authoritative M2 association repository/database; distinct independent database deployments are not proved fenced by this shared root owner.

Standalone Server and SDK-next currently contain no legacy prompt graph (`packages/server/src/routes.ts:49–78`), and can supply a scoped commit-through port for their known no-legacy composition. The shared `ftcHost` callback signature must change there, preserving disabled execution. A separately hosted process cannot infer that an Opencode process elsewhere is idle.
