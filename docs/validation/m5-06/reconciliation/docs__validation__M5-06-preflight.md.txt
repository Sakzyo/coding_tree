  23 ## What the adopted M5-05 producer promises, and what it does not
  24 
  25 The [M5-05 brief](M5-05-brief.md) adopts complete producer-owned saved-source identity, independent configuration identity, an immutable complete snapshot execution lease, interval/change-generation proof through settlement, truthful initial/settlement dirty exclusions, opaque Core-only execution capability, scoped process observation/cancel-and-join, and one owner-issued immutable settled record. It requires exact root/Location/descriptor/wrapper/build-JDK/SDK-recipe binding. A successful dirty saved-basis build remains historical compilation evidence and cannot authorize current displayed-program readiness or deployment.
  26 
  27 It prospectively exposes `build`, `startBuild`, `readBuild`, owner-issued `BuildID`, and running/settled `BuildRecord`; it produces **no artifact**. It retires admissions and joins resources on owner closure, has no automatic retry or durable cross-restart history, and preserves `Java.layer(documentPorts)` with explicit build-enabled composition. These are brief obligations, not findings about an implementation.
  28 
  29 M5-06 therefore needs a retained APK-output capability after process settlement. Actual ordered logs, exit zero, and complete cleanup prove process observations; they do not by themselves identify an APK or prove that a pre-existing path belongs to that run. A lease released at settlement cannot silently become a usable long-lived artifact reader. The frozen producer must show the lifetime/binding M5-06 can consume or the coordinator must deliberately assign its minimal extension.

  46 ## Retained APK output: acceptable boundary options
  47 
  48 Both options below preserve the source contract. The exact choice depends on the frozen M5-05 ports and is a routine runtime-port decision when authority and lifetime remain the same.
  49 
  50 | Option | Required producer guarantees | Consequence |
  51 | --- | --- | --- |

Hash and re-read the same authorized object; a pathname in logs is not a capability. |
  53 | Narrow artifact-store capture port | An explicitly assigned M5 artifact port captures the exact run-bound APK into immutable retained local storage before the execution/output resources retire. The owner stores its canonical identity and protected read capability, not caller-supplied bytes/path/status. | Adds one boundary only if the existing producer cannot retain outputs. Copy/capture failure means no valid artifact. No new filesystem crawler, tool discovery or generic output selector is needed. |
  54 
  55 A trusted adapter must distinguish the APK belonging to this successful run from an unrelated file left in a shared output directory. Do not infer provenance from an APK log line, exit zero, extension, newest file, size/mtime, a caller path, or a glob result. A deterministic new build may produce identical bytes to an earlier build; digest equality does not merge build identities. Whether cache/restored/up-to-date output satisfies produced-APK provenance must be settled through the trusted fixed-recipe adapter's exact run proof; this preflight invents no such production cache proof or support claim. Unsupported/ambiguous multiple outputs or incomplete output provenance must produce absence/invalidity rather than selecting yesterday's APK.
  56 
  57 Successful current evidence is a prerequisite for issuance. Failed/cancelled/outdated/unverifiable runs never issue deployment artifacts or fall back to an older build. Initial/settlement dirty exclusions cannot be relabeled current by later saving a matching buffer. Historical build and artifact records retain their original identity and basis; querying an exact older ID never returns the newest artifact. No durable database, recovery job or global artifact registry is required for the isolated task unless separately authorized.

  59 ## Query validity, path authority and Schema
  60 
  61 Every artifact/verification query resolves the owner-issued build identity under current authoritative project/root/Location placement. Structurally valid caller JSON is a lookup claim, not history or a read capability. Compare all bound identities with the retained owner record; unknown/foreign references and supplied field tampering cannot authorize access. A fresh owner cannot validate an old owner's artifact without an explicitly designed trusted repository, which is outside this preflight.
  62 
  63 For a previously issued reference, fresh verification must establish both the retained APK's content digest and current complete saved-source/configuration identity. Reuse the frozen saved-input authority rather than hashing only opened Java documents. Detect additions/deletions/renames and relevant wrapper/build/resource/configuration changes; output/cache writes alone do not invalidate unless the declared recipe truly consumes them as input. Dirty current inputs invalidate current displayed-program readiness. A dirty exclusion at the build basis remains excluded provenance and cannot become compiled text through an artifact query.
  64 
  65 Current digest equality is different from interval validity. The adopted M5-05 generation proof prevents source/configuration A→B→A during execution from becoming successful current evidence. Artifact queries must preserve that settled result; they cannot resurrect outdated evidence with matching endpoint bytes. For later A→B→A, [design failure contracts](../high-level-design.md#failure-contracts) require a new valid build after relevant source changes. Carry authoritative monotonic change identity or an equivalent trusted invalidation observation where needed; equality of endpoint hashes alone is not proof of no intervening change. No arbitrary polling interval/expiry is introduced. Snapshot-and-verification queries are observations at their boundary, not indefinite robot dispatch authority; M9-04 performs the later refresh.
  66 
  67 Digest-read, currency-read, root-revalidation, unsupported-scope or cleanup failure cannot yield `valid: true` or a fabricated `inputChanged`. Preserve stable structured failure reasons/typed errors according to the frozen owner conventions. Define separately the legitimate no-artifact case, foreign/unknown query, and transient verification failure; do not erase a failure by claiming success with an absent optional reason.
  68

The artifact owner uses a protected retained handle/store binding or equivalent trusted adapter proof at every read; lexical containment or a caller-provided absolute path is insufficient against replacement/symlink/root changes. No arbitrary path is opened based on ref JSON. Keep runtime handles, descriptors, access tokens and machine-private state Core-only. Public projections omit the local host path where unnecessary, as M9 already does, while preserving complete identity/digest. Future transport capability handoff must remain exact-owner-bound; this preflight does not specify or enable installation transport.

Core re-exports those exact values. Use readonly public records, same-name Struct interfaces, stable unique domain identifiers/brands, `create()` for new generated IDs, strict owner-boundary decode, and the package `optional(...)` helper so absent reason/artifact/path projection fields omit `undefined`.
