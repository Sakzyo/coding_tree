## Implementation and decisions

- Schema owns the sole `FtcController.ControllerCandidate` and structured `DiscoveryError`. Public records are readonly Schema values with stable domain identifiers. The canonical current contract is exported from the existing Schema barrel as required by its package guide. Core re-exports those exact schema identities.
- `Controllers.Service` is an Effect facade built by `Controllers.layer(transport)`. Its narrow injected `Adb.DiscoveryTransport.readDevices` accepts only the structured argument tuple `["devices", "-l"]`; it has no install/start/connect/forward/shell or mutation operation. No host binding, daemon, global coordinator, application registry or sibling bootstrap was added.
- Pure `Adb.parseDevices` parses `devices -l` responses. It retains transport address, reported ADB state and optional reported model. Authorization and availability are distinct: `device` yields authorized/available; `unauthorized` yields unauthorized/unauthorized; `offline` yields unknown/offline. Unrecognized states, including the multi-word ADB permission diagnostic, remain unknown/unavailable with `adb_unsupported_state`.
- Ruling agreed with the coordinator: a successful header with no devices yields `[]`; absent/malformed output is `adb_invalid_response`. Missing tools, transport failures and nonzero command exits are typed failures (`adb_missing_tool`, `adb_transport_error`, `adb_command_failed`) rather than fabricated candidates or empty-success results. Invalid rows, invalid metadata, duplicate metadata keys and repeated transport addresses fail the whole response conservatively.
- Exact reported `model:REV_Control_Hub` produces an optional `control-hub` kind hint. Generic Android models remain of unknown kind, including the phone-shaped synthetic fixture. ADB authorization/availability and model hints establish neither FTC compatibility nor stable physical identity. No `controllerID`, alias mapping, target selection, generation or connection descriptor was introduced; those remain later owners' work.
- Language-independent guidance codes cover Control Hub connections, identifying Control Hub/phone hardware, unverified phone compatibility, USB authorization, connection recovery and unobserved Expansion Hub configuration. They are setup/recovery context, not observations of attached Expansion Hubs, wiring or robot configuration. No UI copy or untranslated presentation text was added.
- Import/layer construction does not run discovery. Each call owns an `Effect.scoped` read, preserving interruption and closing the injected transport's per-read finalizers on success, parse failure, command failure, transport failure and cancellation. The external host owns its transport; this task owns no process, polling subscription, forward or persistent/global map to dispose.
