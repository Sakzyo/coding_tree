The injected automatic ports are:

- `authorization.read(PreparationRequest)` returns strictly decoded `PreparationAuthorization`, bound to exact project/profile/component and full artifact source/version/license/SHA-256. License acceptance and system permission come from this trusted host boundary. Changed bindings or malformed evidence fail; absent approval returns a manual license/permission step before download or staging.
- `download.fetch(PreparationRequest)` returns actual bytes. Core hashes those bytes against the catalog digest before staging. The port must enforce the pinned HTTPS source without redirect/source substitution; production network isolation remains an adapter gate.
- `cache.lookup(PreparationRequest)` returns an app-cache asset or `undefined`; cached archive bytes are independently rehashed. A cache success flag cannot substitute actual files.
- `cache.discard(request, asset)` invalidates only the exact strictly decoded rejected lookup entry after byte/path/probe validation fails. Authorization/profile mismatches and malformed references never reach discard. The host adapter enforces owner-controlled cache references, root confinement and atomic quarantine/removal without project/system deletion.
- `cache.stage(request, bytes)` acquires scoped staging and returns canonical `{ archivePath, path }`. The adapter owns safe extraction, isolated paths and removal of all unpublished partial files on scope exit.
- `cache.commit(request, asset)` atomically publishes the already validated asset inside the app cache and makes it discoverable by ordinary probes. Interruption/failure must publish nothing and preserve earlier valid publications. No project dependency or system-wide Java replacement is permitted.
- Existing read-only probes receive an optional staged `path`; Core requires actual tool-path existence plus an available response with that same path and exact pinned version before publication.

Core re-inspects the published component using the normal inspection path. It excludes the candidate descriptor and refuses build dispatch if the resolved profile changed. Downloads, flags or installation alone never establish ready: the shared M4-03 gate still requires all components, matching current build evidence, saved source/configuration identity, a fresh context read and successful scoped cleanup. There is no robot/deployment/start authority in these ports or results.

The Schema additions are canonical current serializable records with stable identifiers. Runtime bytes, cache services, fibers and cancellation handles remain in Core. ## Lifetime and recovery

Each automatic attempt uses the existing per-project check/run scope plus one nested component scope. Download leases and staging finalizers complete before results settle. Cancellation during download or staging publishes no partial asset, never promotes the unfinished component to ready, and preserves components published by previous attempts or another project. An active same-project attempt remains busy. A second project may proceed independently. Service disposal cancels in-flight work, waits for cleanup, and rejects stale handles.

Already valid tools are re-probed and skipped. Each explicit retry/recheck rereads context, dependencies and ordinary tool availability; the selected missing prerequisite also refreshes authorization, cached bytes and staged probes. Failed/cancelled staging is deleted; a fresh attempt can reuse completed tools without reinstalling them. The cache fixture publishes with a real directory rename and preserves previous components.

Persistent corrupt/missing cache entries are rejected before commit and passed to the exact-entry discard port. The current attempt remains visibly failed; the next deliberate retry can download and stage fresh bytes. Discard failure keeps setup failed, and cancellation waits for its scoped lease cleanup without publishing anything. Valid entries are never discarded. Schema-malformed references, authorization mismatches and profile mismatches are not deletion authority. Core performs no deletion; the trusted adapter owns cache-reference validation, atomic invalidation/quarantine and filesystem isolation.
