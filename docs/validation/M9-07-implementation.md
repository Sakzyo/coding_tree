## Independent-review fix round 1 — owned probe cleanup

Fix baseline: `fbea951a370db94684350fdbee9f9a89ab0bb80f`; date 2026-10-06. **BLOCKED status and every external release gate remain unchanged.** The important finding was that a directly killed/exited parent could leave a descendant and inherited output streams alive. The related acquisition finding was that the listener started before temporary-directory allocation entered cleanup.

The runner now starts each POSIX probe in an owned process group. Normal leader exit, deadline expiry, AbortSignal cancellation and registered SIGINT/SIGTERM callbacks share one cleanup promise. Cleanup sends TERM to the group, allows 100 ms, escalates to KILL, and checks group disappearance for at most 1 second. Returned output and cancellation wait for cleanup. Cleanup failure fails the probe and retains its temporary project/cache with an explicit diagnostic. Windows execution fails closed in this runner until a separate process-tree adapter is evaluated; no Windows support is claimed. This is cleanup of the owned, non-escaping fixture process group, **not containment of hostile descendants that create another session**.

A real `/bin/sh` fixture starts a harmless 30-second sleep that ignores TERM and holds inherited output pipes. Three tests cover leader exit, timeout and AbortSignal cancellation. Each requires bounded completion and verifies both recorded PIDs no longer exist before safety cleanup. The independent test-finally cleanup prevents the intentional RED run from leaving its children alive. SIGINT/SIGTERM callbacks use the same cancellation path but direct OS-signal interruption was not separately exercised. The listener is now created inside the acquired directory's cleanup scope; listener disposal finishes before directory deletion, including listener-allocation failures.
