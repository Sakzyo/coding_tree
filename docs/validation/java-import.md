# M5-03 — FTC-aware Java import evaluation

Date: 2026-10-06. Review base: `75f1038c48f7b5c9afbbba91fef837d2a7794506`.

**Decision: gate remains OPEN.** Do not register a production language service or promote an M4 supported profile. JDT LS 1.46.1's experimental native Android importer did not resolve the tested, compiling FTC projects. An evaluation-only Eclipse shadow populated from the real Gradle compiler classpath resolved every tested symbol on macOS arm64. Windows has not run. This is evidence for further adapter work, not a completed editor or AC-04.

Thus these evaluation pins must not be copied blindly into a production download catalog. Why this candidate: 1.46.1 is an immutable milestone with a Java 21 floor and explicit experimental Android support in its [versioned README](https://github.com/eclipse-jdtls/eclipse.jdt.ls/blob/v1.46.1/README.md). The existing application's `latest` snapshot launcher was not reused.

## Actual host observations

Four checks were required per domain: **completion** of a real member from a partial token; **definition** landing in the expected dependency or generated source; **clean semantic diagnostics** for valid code (syntax-only fallback rejected); and **error diagnostics** after replacing that member with `missingM503Symbol` in the in-memory document. The diagnostic must explicitly identify the nonexistent symbol with error severity. No code was deployed.

After successful Gradle compilation, native JDT LS emitted `ServiceReady` but each probe carried `... is not on the classpath of project TeamCode, only syntax errors are reported`. ## Setup failures distinguished from compatibility results

- The first owned Gradle init script had a missing brace. It was repaired before compatibility observations. A first direct `debugCompileClasspath.files` query also encountered variant ambiguity; the final fallback uses the real JavaCompile task instead.
- TeamCode does not enable BuildConfig generation in this upstream version. The first generated probe used the wrong package. It was corrected to FtcRobotController's actual generated class, and then compiled successfully before the authoritative native rerun. [Successful baseline compile](m5-03/gradle-native-compile.log).
- Initial offline resolution lacked AndroidX artifacts. An online, owned-cache compile provisioned the declared dependencies. That command inadvertently allowed AGP to install platform-tools **37.0.1 into `/private/tmp/m5-03-tools/sdk`**, using byte-identical copies of the user's already-existing license files. No `sdkmanager --licenses` or new license-acceptance action ran; the installed SDK remained platform-tools **35.0.1**. The exact action is retained in [provisioning log](m5-03/gradle-provision.log), and license digests in [environment log](m5-03/environment.log). All later Gradle commands and JDT Gradle arguments set `-Pandroid.builder.sdkDownload=false`; reruns must copy existing platform-tools before enabling dependency downloads.
- Road Runner's first shadow completion test accidentally selected `pose` instead of the `position` member because they share `pos`. The [cursor regression](m5-03/cursor-red.log) failed before correction; [Python test](m5-03/cursor-green.log) and [real rerun](m5-03/shadow-roadrunner-test.log) passed afterwards. The initial failure is preserved in [its log](m5-03/shadow-roadrunner-cursor-error.log).
- Sandboxed Gradle and existing HTTP/WebSocket adapter tests could not create required loopback sockets. Their reruns used authorized host execution on owned fixtures. The [adapter sandbox failure](m5-03/covering-sandbox-denied.log) is not a product regression.

## Reproduction

Working directory for Bun tests/typechecking is `packages/core`; lint/format and the Python unit test run at repository root. Prepend `/private/tmp/ftc-bun-1.3.14/bun-darwin-aarch64` to PATH. Real probes require explicit `M503_CONFIG`; absent assets skip, never pass. Never point these preparation scripts at a team checkout, user Gradle home, or installed SDK as their writable destination.

1. Provision the exact Eclipse archive above, compare its published checksum, and unpack to an owned `jdtls` directory. Retrieve the exact FTC source commit archive and compare its recorded hash. Verify explicit Java 21 and build Java 17 executables. Copy the installed Gradle cache and Android API 30, build-tools 34.0.0, **platform-tools**, and existing license-state files into an owned directory. Copying existing state is not permission to accept a new license; stop if a new license is needed. Use explicit Gradle 8.9. No wrapper or SDK auto-download is necessary.
2. Start from [saved native configuration](m5-03/native-config.json), replace local paths with the owned/verified paths on the rerun host, and set the intended result JSON path. Preserve the canonical artifact fields. The harness checks the two Java executable and JDT archive digests before launching.
3. From the repository root, using `F=packages/core/test/ftc-adapters/fixtures/java-import`:

   ```sh
   /usr/bin/python3 "$F/prepare.py" tools.json EXTRACTED_FTC NEW_NATIVE native.json
   /usr/bin/python3 "$F/pathing.py" native.json NEW_PEDRO pedro pedro.json
   /usr/bin/python3 "$F/pathing.py" native.json NEW_ROADRUNNER roadrunner roadrunner.json
   ```

   These destinations must not already exist. The scripts add small probes or one pathing dependency to owned fixtures, never alter user projects. Pedro core/ftc 2.1.2 are in Maven Central; the extra historical Pedro repository in the fixture is not required for those artifacts.

4. For each native project, run the actual compiler/snapshot task. First provision missing declared dependencies online if necessary; then repeat with `--offline`. Keep SDK downloads disabled in both modes:

   ```sh
   JAVA_HOME=EXPLICIT_BUILD_JDK EXPLICIT_GRADLE/bin/gradle \
     --offline --no-daemon --console=plain -Pandroid.builder.sdkDownload=false \
     -g OWNED_GRADLE_HOME -p OWNED_PROJECT \
     -I ABSOLUTE_REPO/packages/core/test/ftc-adapters/fixtures/java-import/classpath.init.gradle \
     :TeamCode:m503Snapshot
   ```

5. From `packages/core`, run `M503_CONFIG=ABSOLUTE_CONFIG bun test ./test/ftc-evaluation/m5-03.test.ts` for the native configs. The recorded candidate is expected to fail the semantic checks above; retain the failure, do not alter the expectations.
6. From the root, create each separate shadow with `/usr/bin/python3 "$F/shadow.py" native.json NEW_SHADOW shadow.json` (likewise Pedro/Road Runner), then run the same Bun test with that shadow config. Expected on the recorded macOS combination: all observations true, Windows skipped. The generated-source and binary-copy inventories are saved in each shadow's `provenance.json`.
7. Run the deterministic/covering commands in the implementation report. Stop only the owned Gradle user home (`EXPLICIT_GRADLE/bin/gradle --stop -g OWNED_GRADLE_HOME`), verify no owned processes remain, and remove disposable fixtures/caches when review no longer needs them.

Every LSP run copies its Eclipse configuration, creates an isolated workspace/home, launches a new process group and disposes it on exit/timeout/abort. Gradle daemons create separate sessions, so the harness additionally calls `--stop` against only its dedicated Gradle user home. The process-tree tests include TERM-resistant descendants retaining output pipes. [Post-run process inspection](m5-03/process-check.log) found only the inspection shell/rg, no JDT client/server or Gradle daemon. Per-run workspaces were removed. The coordinator explicitly requested retaining `/private/tmp/m5-03-tools` (downloads, copied SDK/cache, projects and configs) through independent review and follow-on tasks; the coordinator owns its later targeted cleanup.

Windows rerun remains blocked by the absent host and an unverified Windows Job Object/process-tree owner. The launch recipe can express Windows paths, but the execution harness deliberately rejects Windows until that ownership boundary exists. Do not call a POSIX cleanup result Windows evidence.

## Remaining gates

- Native Android import for this candidate fails. A production adapter decision, shadow refresh/source mapping, source attachment, unsaved edits and scope disposal integration require further design/implementation; none is enabled here.
- Windows x64/arm64 combinations and their subprocess cleanup: NOT RUN. No platform support promotion.
- Complete JDK package provenance, packaging/resource limits, genuine disconnected operation and the packaged Monaco/editor flow: NOT RUN; local Gradle offline mode is not proof of network isolation.
- Full Pedro FTC and Road Runner Dashboard/tuning workflow compatibility is not established by these sampled symbols.
- M9-07/M9-08 production command isolation remains open. No command/build/robot production registration, SDK setup service, model loop or controller action was added.
