## Behavioral and lifetime decisions

- Canonical `ProjectContext.projectID` is the association ID, distinct from `location.project.id`; full project/chat/Session identity keys drafts, selections and asynchronous targets. Canonical roots are copied unchanged, with no filesystem recanonicalization. Supplied records are copied/frozen before entering mutable UI stores or command calls.
- Query pending/failure is separate from successful idle. A scoped owner event retires the older initial owner snapshot; late target queries are cancelled/ignored. A newer owner event also supersedes an older busy submission result. Successful owner events recover failed ownership observation while preserving draft text and emitting no submission.
- Admission captures text plus its local edit revision. It clears only the unchanged original draft; an edit-and-revert, another chat's text, or later selection survives. Busy/errors retain drafts and never schedule retries. A foreign busy owner or admission receipt is a membership failure, not a fallback Session command.
- Stop captures the displayed exact owner and never labels the project idle by itself. Both frame and supplied-slot stop actions preserve that target. Unmount aborts observation/command lifetimes and guards work not yet invoked; it never stops domain execution. Each rendered slot has a lifetime guard, and fresh component instances have independent state.
- Reopen recovery sends the displayed project's exact canonical FolderRequest, rather than opening a picker that could change the target. Generic Retry only rechecks observations; it does not replay create/submit/stop. With no known projects, failed association is still visible and the create/open actions permit deliberate retries.
- Known projects are supplied as an initial immutable catalog. Successful explicit association commands add their canonical returned context to the presentation cache. This is not another association store or persistence layer.
